## ✅ Аудит безпеки (зроблено перед планом)

### 1. Чи видаляються старі розмови? — **НІ**
Проаналізовано весь код нової версії (staging 17.0.1.4.0):
- `channel_conversation.py` — лише **створює** `discuss.channel` та `channel.message`, **немає** `unlink`/`delete` розмов
- `mail_channel.py` — лише маршрутизація вихідних повідомлень
- `channel_message.py` — захист від дублікатів (не видалення)
- `channel_backend.py` — крон повторної відправки `failed` повідомлень

**Жодного видалення розмов у новій версії немає.**

### 2. Міграції (виконаються при оновленні) — **БЕЗПЕЧНІ**
- **`17.0.1.1.0/post-migrate.py`** — видаляє лише **осиротілий cron** `ir_cron_bridge_switch_check` (падав кожні 30 хв з `AttributeError`). Не торкається розмов. Ідемпотентна.
- **`17.0.1.2.0/post-migrate.py`** — **бекфіл** `webhook_path_id` для Telegram-бекендів (генерує випадковий шлях). Не видаляє розмови. Ідемпотентна.

### 3. Ключі (Telegram/SendPulse) — **НЕ ВТРАТЯТЬСЯ**
Модуль читає ключі через **`ir.config_parameter`** (в БД Odoo), а не з файлів. Заміна коду модуля не зачепить ключі.

### 4. Права доступу — **ВИПРАВЛЕНО**
Після клону обов'язково `chmod -R o+rX .` (урок зі staging + урок з fayna_sentry сьогодні).

## 📋 Кроки виконання

### Крок 1: Бекап (обов'язково, #PROD)
- Свіжий повний бекап БД + filestore **поза addons-path** (урок зі staging)
- Перевірити валідність бекапу (розмір, цілісність)
- Вже є сьогоднішній бекап 7.5G + borg офсайт, але робимо свіжий перед зміною

### Крок 2: Отримання коду
- Клонувати `fayna-channel-bridge` з GitHub (як на staging) замість копії
- `chmod -R o+rX .` вручну (хука post-merge на проді немає)
- Перевірити, що модуль читабельний для odoo-користувача (урок з fayna_sentry)

### Крок 3: Оновлення модуля
- `docker exec campscout_web odoo -u fayna_channel_bridge -d campscout --stop-after-init`
- Виконаються міграції 1.1.0 + 1.2.0 (безпечні, див. аудит)
- Перевірити логи на помилки

### Крок 4: Перереєстрація вебхука Telegram
- Міграція 1.2.0 НЕ робить перереєстрацію (це мережевий виклик)
- Перереєструвати через кнопку/cron модуля
- **Увага:** це може тимчасово перервати Telegram-інтеграцію

### Крок 5: Верифікація
- HTTP 200 на публічному сайті
- Розмови на місці (перевірити кількість `channel.conversation` / `channel.message` до/після)
- Вебхук Telegram працює
- Логи без помилок

### Крок 6: Відкат (якщо щось піде не так)
- Відновити з бекапу (крок 1)
- Повернути стару копію модуля

---

## ⚠️ Ризики
1. **Перереєстрація вебхука** — тимчасова перерва Telegram-інтеграції (крок 4)
2. **Права доступу** — якщо забути `chmod`, буде `KeyError: 'assets'` (як сьогодні з fayna_sentry)
3. **Міграції** — низький ризик, обидві ідемпотентні та не видаляють розмови

## ✅ Гарантії
- Старі розмови **не видаляються** (підтверджено аудитом коду)
- Ключі **не втрачаються** (в БД, не в файлах)
- Повний бекап перед зміною + можливість відкату
